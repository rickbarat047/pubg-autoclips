# PUBG AutoClips

A **free, local-first** Windows desktop application that analyses complete PUBG
match recordings and produces vertical 1080×1920 short-form MP4 clips. It uses
kill-feed OCR, local audio analysis and lightweight OpenCV visual analysis to
rank highlight candidates. No cloud services, paid APIs or mandatory online AI.

> **Honesty note:** Detection accuracy on real PUBG footage has **not** been
> validated. OCR cannot reliably distinguish a kill from a knock unless the
> feed text itself says so. Clutch events are labelled *candidates*, never
> verified 1v2/1v3/1v4. See [Limitations](#limitations).

---

## Features

### Working
- Import MP4/MKV recordings with drag-and-drop; FFprobe metadata extraction.
- First-run onboarding: IGN, screenshot-based kill-feed calibration (normalised
  region), OCR test, output folder.
- Full-match analysis in background QThreads — GUI never freezes.
  - Kill-feed OCR via RapidOCR (ONNX Runtime, CPU) with configurable sampling,
    confidence threshold, multi-observation confirmation and duplicate
    suppression.
  - Streaming audio RMS/spectral analysis (never loads full audio into RAM).
  - OpenCV motion + scene-change analysis.
  - Transparent weighted event scoring with per-signal evidence breakdown.
  - Multi-kill / clutch-*candidate* grouping.
  - Clip selection with pre/post-roll, min/max duration, overlap merging and
    duplicate removal.
- SQLite persistence (settings, matches, jobs, events, highlights, exports)
  with schema migrations.
- Vertical export via FFmpeg with three layouts (blurred background default,
  crop, pillarbox), original audio preserved, H.264/AAC MP4.
- Highlight gallery with thumbnails, filters, keep/discard and multi-export.
- Simple clip editor with scrubbing, boundary adjustment and vertical preview.
- Dashboard with live statistics; About page; settings for all major knobs.
- Automated pytest suite with synthetic video fixtures.

### Not implemented / explicitly limited
- No verified kill-vs-knock classification from OCR alone.
- No verified clutch (1vX) labelling — evidence is insufficient.
- No player-count / HP / alive-counter detection (would require additional HUD
  models not shipped in v1).
- No GPU (CUDA or AMD) inference for OCR — CPU ONNX only.
- No non-MP4-specific codec transcoding beyond what FFmpeg supports.
- No automatic re-encoding of unsupported source codecs before analysis.
- PyInstaller build is supplied but **not** verified on a clean Windows install.

## Requirements

- Windows 11 64-bit
- Python 3.11 64-bit (3.11.9 recommended)
- FFmpeg + FFprobe (see below)
- Target hardware: i5-12400F, RX 6700 XT, 16 GB RAM (CPU-only inference)

## Installation (development)

```powershell
# From the project root
powershell -ExecutionPolicy Bypass -File scripts\setup_windows.ps1
```

The setup script creates `.venv`, installs dependencies, checks Python/FFmpeg,
verifies RapidOCR initialisation and runs an import check.

### FFmpeg
FFmpeg is **not bundled** by default. Install it either way:

1. Download an essentials build from <https://www.gyan.dev/ffmpeg/builds/> and
   place `ffmpeg.exe` and `ffprobe.exe` in `bin/`, **or**
2. Install FFmpeg and add it to your `PATH`.

Set explicit paths in **Settings → System** if auto-detection fails.

RapidOCR ships its ONNX models inside the Python package — nothing is
downloaded at runtime. Analysis and export work fully offline.

### FFmpeg licensing
- gyan.dev **essentials** builds: LGPL 2.1 or later.
- gyan.dev **full** builds: GPL 2 or later.
- If you redistribute FFmpeg binaries with your build you must comply with the
  applicable licence (source offer for LGPL, GPL licence text for GPL builds).
  See `FFMPEG-LICENSE.txt` generated by the build script.

## Launch

```powershell
.\.venv\Scripts\python.exe -m app.main
```

Run tests:

```powershell
.\.venv\Scripts\python.exe -m pytest -q
```

### Windows executable build

```powershell
powershell -ExecutionPolicy Bypass -File scripts\build_windows.ps1
```

Output: `dist\PUBGAutoClips\PUBGAutoClips.exe` (one-folder distribution; verified
to build and launch on Windows 11, but not tested on a clean machine).
Bundling FFmpeg into `bin/` before building makes the export workflow available
in the built app; observe the licence terms above. The development environment
here uses a BtbN **GPL** shared build in `bin/` (libx264 + AMF), so GPL terms
apply to redistributed builds containing it.

Exported clips default to `G:\PUBG AUTOCLIPS\exports` unless you set
an output folder during onboarding or in Settings.

## Workflow

1. **Onboard** — enter IGN, calibrate kill-feed region from a screenshot,
   choose output folder.
2. **Import** an OBS MP4 recording on the Import page.
3. **Analysis** starts automatically; progress for OCR/audio/visual/scoring is
   shown live. You can pause or cancel safely.
4. **Highlights** — review cards, preview, filter, keep/discard.
5. **Editor** — scrub and adjust start/end, check the vertical preview.
6. **Export** — by default the top clips are exported automatically right
   after analysis (disable in Settings → Export). You can also choose clips
   manually in the gallery. Each becomes its own vertical MP4 in the output
   folder. Exports are validated for resolution/codec/duration.

## Architecture

```
app/
  main.py, bootstrap.py, config.py
  core/         project/job/queue/event-bus/exceptions
  database/     db.py, models.py, migrations.py
  media/        probe, validator, decoder, reader, thumbnail
  detection/
    pipeline.py
    kill_feed/   ocr_engine, feed_detector, ign_matcher, calibration
    audio/       audio_analyzer, energy_detector, combat_detector
    vision/      motion_detector, scene_detector, activity_detector
    scoring/     event_scorer, clutch_detector, event_ranker
  clips/        clip_selector, clip_boundaries, clip_merger, duplicate_remover
  rendering/    ffmpeg_runner, vertical_layout, audio_mixer, export_manager
  workers/      analysis_worker, export_worker, thumbnail_worker
  ui/           main_window + pages + widgets
  utils/        paths, logging, hardware
```

Detection engines are separate modules behind small interfaces, so they can be
replaced later (e.g. a HUD reading model instead of OCR).

### Data storage
Application data lives under the platformdirs user data directory
(e.g. `%LOCALAPPDATA%\PUBG AutoClips`). Large video files are **never** stored
in SQLite — only paths and metadata.

## Scoring model (starting weights — not validated PUBG metrics)

| Signal | Weight |
|---|---|
| Confirmed IGN elimination | 40 |
| Multi-kill bonus | +15 (and grouped count) |
| Audio intensity | up to 15 |
| Visual activity | up to 10 |
| Sustained combat | up to 10 |
| Scene context | up to 5 |
| Detection uncertainty | penalty up to 20 |

Every event stores its evidence and per-signal breakdown so scores are
explainable, and all weights are configurable in `config.py` / settings.

## Performance notes

- **One-pass frame extraction**: FFmpeg decodes the video once and writes only
  sampled frames (one every 2 s by default). This replaced slow OpenCV seeking
  per frame. A 16-minute 1080p match extracts ~500 frames in ~10 seconds.
- OCR and visual analysis share those same frames — no second decode pass.
- OCR uses a max-side detection limit and skips orientation classification,
  making each crop ~4x faster with no loss of kill-feed readability.
- Audio is streamed as 1-second PCM chunks in a parallel thread.
- Adaptive sampling caps long recordings at ~900 samples regardless of length.
- Balanced preset (default): 2 s sampling; Fast: 3 s; Accurate: 1 s.
- Measured on a 16.6-minute 1080p match: **~87 seconds end-to-end** (previously
  over 30 minutes), producing real IGN-matching kill events and clips.
- OCR, analysis and rendering run in QThreads; the event loop stays responsive.

## Limitations

- OCR quality depends heavily on your HUD, resolution, text size and recording
  compression. Calibrate carefully and tune the confidence threshold.
- Kill-feed rows persist on screen for several seconds; the detector confirms
  IGN sightings over consecutive samples and applies a time cooldown, but false
  positives/negatives are possible. The whole OCR line is not used as a dedup
  key because the alive-counter/compass inside the region changes continuously.
- "FUNNY_CANDIDATE" and "LONG_RANGE_CANDIDATE" categories are reserved but not
  automatically detected in v1.
- Hardware (AMD AMF) encoding is offered only if your FFmpeg build exposes
  `h264_amf`; CPU `libx264` is the reliable fallback.
- Vertical blurred-background layout avoids cropping the kill feed/minimap;
  the *crop* preset intentionally fills the frame and **can crop HUD elements**.
